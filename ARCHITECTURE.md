# Architecture

ZeroChart is a TanStack Start (React 19, SSR) app deployed on Vercel, backed by
Supabase (Postgres + RLS, pg_cron, Deno Edge Functions), plus a TradingView Pine
Script HUD that ports the scoring model to the chart (close to, but not identical with, the
app's; see `docs/PINE_PARITY_ASSESSMENT.md`).

Tooling config (`vite.config.ts`, `vitest.config.ts`, `tsconfig.json`,
`eslint.config.js`, `sonar-project.properties`, `.sonarcloud.properties`,
`components.json`) stays at the root, where each tool looks for it. `src/routes`,
`supabase/` and `public/` are fixed by TanStack Start, the Supabase CLI and Vite.

`.zerochart-evaluations/`, `.zerochart-campaigns/` and `.zerochart-reports/` are
local, git-ignored stores written by `npm run evaluate`.

## Rules of thumb

- Engines in `src/lib` stay pure (no React, no network) so Vitest can cover them;
  the edge functions follow the same split (`index.ts` wires Deno, sibling files
  hold the testable logic).
- The database owns money and permissions: paper fills, signal ingestion and RLS
  live in SQL migrations and are covered by `supabase/tests`.
- Schema changes ship as new migrations only; see `docs/RELEASE.md` for the
  order of operations.
